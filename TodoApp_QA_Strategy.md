# Анализ архитектуры TodoApp и стратегия QA-тестирования

## 📋 Обзор проекта

**TodoApp** — это React-приложение для управления задачами с расширенными возможностями:
- **Stack**: React + TypeScript + Vite + Material-UI
- **Развертывание**: PWA (Progressive Web App) + Netlify
- **Доступ**: https://react-cool-todo-app.netlify.app/

---

## 🏗️ Архитектура приложения

### 1. **Слои архитектуры**

```
┌─────────────────────────────────────────────────────┐
│                   UI Components                      │
│  (TasksList, EditTask, SettingsDialog, etc.)         │
├─────────────────────────────────────────────────────┤
│                Context/State Management              │
│  (UserContext, TaskContext)                          │
├─────────────────────────────────────────────────────┤
│                  Custom Hooks                        │
│  (usePeerSync, useStorageState, useOnlineStatus)     │
├─────────────────────────────────────────────────────┤
│                  Utilities & Services                │
│  (syncUtils, githubApi, colorUtils)                  │
├─────────────────────────────────────────────────────┤
│           Local Storage + IndexedDB + WebRTC         │
└─────────────────────────────────────────────────────┘
```

### 2. **Ключевые компоненты и их роли**

| Компонент | Назначение | Критичность |
|-----------|-----------|------------|
| **UserContext** | Управление состоянием пользователя (настройки, темы, данные) | ⭐⭐⭐ Критично |
| **TaskContext** | Управление списком задач и категорий | ⭐⭐⭐ Критично |
| **TasksList** | Отображение и фильтрация задач | ⭐⭐⭐ Критично |
| **EditTask** | Создание/редактирование задач | ⭐⭐⭐ Критично |
| **ShareDialog** | Общий доступ по ссылке/QR-коду | ⭐⭐ Высокий приоритет |
| **Sync** (WebRTC) | P2P синхронизация между устройствами | ⭐⭐ Высокий приоритет |
| **SettingsDialog** | Управление настройками приложения | ⭐⭐ Высокий приоритет |
| **ImportExport** | Импорт/экспорт задач JSON | ⭐⭐ Высокий приоритет |

### 3. **Основные страницы (Routes)**

```
/                 → Главная страница (список задач)
/add              → Добавить новую задачу
/edit/:id         → Редактировать задачу
/categories       → Управление категориями
/sync             → P2P синхронизация
/transfer         → Передача данных между устройствами
/settings         → Настройки приложения
/purge            → Удаление всех данных
/share            → Общий доступ к задачам
```

## 🔄 Критические пользовательские потоки

### **Поток 1: Создание и управление задачами (КРИТИЧНЫЙ)**

**Описание**: Основной функционал приложения

**Шаги**:
1. Пользователь открывает приложение
2. Нажимает кнопку "+ Добавить задачу"
3. Вводит название задачи (макс 256 символов)
4. Добавляет описание (макс 2048 символов)
5. Выбирает/создает категорию
6. Выбирает эмодзи для задачи
7. Устанавливает дату выполнения (опционально)
8. Нажимает "Сохранить"
9. Задача появляется в списке
10. Пользователь может редактировать/удалить задачу

**Проверяемые аспекты**:
- ✓ Успешное добавление задачи
- ✓ Валидация длины названия и описания
- ✓ Отображение в списке и фильтрах
- ✓ Сохранение в локальное хранилище
- ✓ Отмечение как выполненной (чекбокс)
- ✓ Удаление задачи
- ✓ Редактирование всех полей

**Test Cases** (Playwright):
```gherkin
Scenario: Успешное создание задачи
  When пользователь нажимает кнопку "Добавить"
  And вводит название "Купить молоко"
  And выбирает категорию "Покупки"
  And выбирает эмодзи 🛒
  And нажимает "Сохранить"
  Then задача появляется в списке
  And данные сохраняются в localStorage
```

### **Поток 2: Фильтрация и поиск задач (КРИТИЧНЫЙ)**

**Описание**: Поиск и организация задач

**Шаги**:
1. Пользователь видит список всех задач
2. Нажимает на фильтр по категории
3. Видит только задачи выбранной категории
4. Может использовать поисковую строку
5. Может отфильтровать по статусу (выполнено/не выполнено)
6. Может сортировать по дате, алфавиту, приоритету

**Проверяемые аспекты**:
- ✓ Отображение всех задач по умолчанию
- ✓ Фильтр по категориям работает корректно
- ✓ Поиск ищет в названии и описании
- ✓ Фильтр выполненных/невыполненных задач
- ✓ Сортировка работает
- ✓ Комбинированные фильтры работают

---

### **Поток 3: Синхронизация между устройствами (WebRTC) (ВЫСОКИЙ ПРИОРИТЕТ)**

**Описание**: P2P синхронизация задач без облака

**Шаги**:
1. Пользователь открывает страницу "Синхронизация"
2. Видит QR-код своего устройства
3. На втором устройстве сканирует QR-код
4. Выбирает режим синхронизации (одностороннее/двустороннее)
5. Выбирает какие данные синхронизировать
6. Запускает синхронизацию
7. Данные передаются через WebRTC P2P
8. На обоих устройствах отображается статус синхронизации

**Проверяемые аспекты**:
- ✓ QR-код генерируется корректно
- ✓ Соединение WebRTC устанавливается
- ✓ Данные передаются полностью
- ✓ Конфликты задач разрешаются (по дате редактирования)
- ✓ Синхронизация завершается успешно
- ✓ Offline режим не блокирует работу

### **Поток 4: Общий доступ к задачам (ВЫСОКИЙ ПРИОРИТЕТ)**

**Описание**: Поделиться задачами с другим пользователем

**Шаги**:
1. Пользователь выбирает задачу/категорию
2. Нажимает кнопку "Поделиться"
3. Выбирает способ (Ссылка/QR-код)
4. Копирует ссылку или сохраняет QR-код
5. Отправляет другому пользователю
6. Другой пользователь открывает ссылку
7. Видит предпросмотр общих задач
8. Может импортировать их в свой список

**Проверяемые аспекты**:
- ✓ Ссылка генерируется корректно
- ✓ QR-код содержит правильные данные
- ✓ По ссылке открывается правильный контент
- ✓ Импорт создает локальные копии (не синхронизирует)
- ✓ URL безопасно кодирует данные

**Проверяемые аспекты**:
- ✓ Экспорт включает все задачи и категории
- ✓ JSON валиден и полный
- ✓ Импорт корректно парсит JSON

## 📝 Примеры тест-кейсов для Playwright

```typescript
// test/todoapp.spec.ts

test.describe("TodoApp QA Tests", () => {
  
  test.beforeEach(async ({ page }) => {
    await page.goto('https://react-cool-todo-app.netlify.app/');
    await page.waitForLoadState('networkidle');
  });

  // КРИТИЧНЫЙ: Создание задачи
  test("should create a new task successfully", async ({ page }) => {
    await page.click('[aria-label="Add task"]');
    await page.fill('input[name="taskName"]', 'Test Task');
    await page.fill('textarea[name="description"]', 'Test Description');
    await page.click('button:has-text("Save")');
    
    const taskItem = await page.locator('text=Test Task');
    await expect(taskItem).toBeVisible();
  });

  // КРИТИЧНЫЙ: Отмечание как выполненной
  test("should mark task as completed", async ({ page }) => {
    // Create task first
    await page.click('[aria-label="Add task"]');
    await page.fill('input[name="taskName"]', 'Complete me');
    await page.click('button:has-text("Save")');
    
    // Mark as done
    const checkbox = await page.locator('input[type="checkbox"]').first();
    await checkbox.check();
    
    const taskItem = await page.locator('text=Complete me');
    await expect(taskItem).toHaveClass(/completed/);
  });

  // КРИТИЧНЫЙ: Фильтрация
  test("should filter tasks by category", async ({ page }) => {
    await page.click('button:has-text("Work")'); // category filter
    
    const visibleTasks = await page.locator('[data-category="work"]');
    const allTasks = await page.locator('[data-testid="task-item"]');
    
    expect(await visibleTasks.count()).toBeLessThanOrEqual(await allTasks.count());
  });

  // ВЫСОКИЙ: Импорт
  test("should import tasks from JSON", async ({ page }) => {
    await page.goto(page.url() + '/settings');
    await page.click('button:has-text("Import")');
    
    const fileInput = page.locator('input[type="file"]');
    await fileInput.setInputFiles('example-import.json');
    
    const confirmBtn = page.locator('button:has-text("Confirm")');
    await confirmBtn.click();
    
    // Verify tasks were imported
    await expect(page.locator('[data-testid="task-count"]')).toContainText(/\d+/);
  });

  // СРЕДНИЙ: Переключение темы
  test("should toggle dark mode", async ({ page }) => {
    const themeSwitcher = page.locator('button[aria-label="Toggle theme"]');
    const body = page.locator('body');
    
    const initialClass = await body.getAttribute('class');
    await themeSwitcher.click();
    
    const newClass = await body.getAttribute('class');
    expect(initialClass).not.toBe(newClass);
  });

  // Проверка LocalStorage
  test("should persist tasks in localStorage", async ({ page, context }) => {
    // Add task
    await page.click('[aria-label="Add task"]');
    await page.fill('input[name="taskName"]', 'Persistent Task');
    await page.click('button:has-text("Save")');
    
    // Get localStorage
    const storage = await page.evaluate(() => localStorage.getItem('todoapp_tasks'));
    expect(storage).toContain('Persistent Task');
  });
});
```

## 🔍 Рекомендации по автоматизации

### Тесты для Playwright:

1. **Smoke Tests** (5-10 тестов)
   - Приложение загружается
   - Основные кнопки работают
   - Данные загружаются

2. **Core Functionality Tests** (15-20 тестов)
   - CRUD операции с задачами
   - Фильтры и поиск
   - Сохранение данных

3. **Integration Tests** (10-15 тестов)
   - Синхронизация
   - Импорт/Экспорт
   - WebRTC соединение

4. **Edge Cases** (10-15 тестов)
   - Валидация максимальной длины
   - Спецсимволы в названии
   - Очень большое количество задач (1000+)
   - Offline режим
   - Быстрое добавление/удаление

5. **Visual Regression Tests** (5-10)
   - Регулярный снимок экранов
   - Сравнение с базовыми снимками

---

## 📊 Примерный план автоматизации

| Фаза | Тесты | Время |
|------|-------|-------|
| Phase 1 (Week 1) | Smoke + Core CRUD | 40-60 тестов |

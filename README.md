# AITest

# Todo App Test Automation

Проект автоматизации тестирования Todo-приложения с использованием **Playwright**, **TypeScript** и архитектуры **Page Object Model (POM)**.  - https://github.com/maciekt07/TodoApp

---

## 🎥 Видео демонстрации

Видео находится в папке:

`assets/demo`

## Описание проекта

Цель проекта — продемонстрировать практический подход к автоматизации тестирования пользовательских сценариев:

* создание задачи;
* редактирование задачи;
* завершение задачи;
* удаление задачи.

Проект построен с использованием Page Object Model, что позволяет отделить тестовую логику от работы с UI и сделать тесты более поддерживаемыми и масштабируемыми.

## Реализованные тестовые сценарии

### TC-001 Создание задачи

Проверяет возможность создания новой задачи.

Шаги:

1. Открыть приложение.
2. Нажать кнопку Add Task.
3. Заполнить название и описание.
4. Создать задачу.

Ожидаемый результат:

* новая задача отображается в списке задач.

---

### TC-002 Редактирование задачи

Проверяет возможность изменения существующей задачи.

Шаги:

1. Создать задачу.
2. Открыть меню задачи.
3. Выбрать пункт Edit.
4. Изменить название задачи.
5. Сохранить изменения.

Ожидаемый результат:

* задача отображается с новым названием.

---

### TC-003 Завершение задачи

Проверяет возможность перевести задачу в статус выполненной.

Шаги:

1. Создать задачу.
2. Открыть меню задачи.
3. Выбрать пункт Mark as done.

Ожидаемый результат:

* задача помечается как выполненная.

---

### TC-004 Удаление задачи

Проверяет возможность удаления задачи.

Шаги:

1. Создать задачу.
2. Открыть меню задачи.
3. Выбрать пункт Delete.
4. Подтвердить удаление.

Ожидаемый результат:

* задача удаляется из списка.

## Архитектурный подход

### Page Object Model

Вся работа с UI вынесена в отдельные Page Objects.

Пример:

```ts
await todo.createTask(title, description);
await todo.editTask(oldTitle, newTitle);
await todo.deleteTask(title);
```

Такой подход позволяет:

* уменьшить дублирование кода;
* повысить читаемость тестов;
* упростить поддержку тестового набора.

---

## Управление тестовыми данными

Тестовые данные отделены от тестовой логики.

Пример:

```ts
export const tasks = {
  create: {
    title: "Original task",
    desc: "desc",
  },
  update: {
    title: "Updated task",
  },
};
```

Преимущества:

* переиспользование данных;
* упрощение поддержки тестов;
* возможность перехода к data-driven подходу.

## Работа с нестабильным UI

Во время разработки были выявлены проблемы, характерные для React/MUI приложений:

* динамический ререндер компонентов;
* анимации и transition-эффекты;
* нестабильные локаторы.

Для повышения стабильности тестов были использованы следующие решения:

* отказ от общих текстовых локаторов;
* привязка действий к контейнеру задачи;
* использование более надежных селекторов;
* применение force click в случаях нестабильного UI;
* ожидание изменения состояния интерфейса вместо фиксированных задержек.

## Запуск тестов

Установка зависимостей:

```bash
npm install
```

Запуск всех тестов:

```bash
npx playwright test
```

Запуск в режиме браузера:

```bash
npx playwright test --headed
```

Запуск отдельного теста:

```bash
npx playwright test -g "TC-002"
```

Просмотр отчета:

```bash
npx playwright show-report
```
